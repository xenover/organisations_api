# Reporting security concerns

This is a local demonstration project. Maintenance targets the current `master`
branch on Node 24; there is no supported production deployment or separate
long-term release line.

Check the repository's [Security page](https://github.com/xenover/organisations_api/security).
If GitHub offers **Report a vulnerability**, use that private reporting form.
Otherwise, [open an issue](https://github.com/xenover/organisations_api/issues/new)
asking the maintainer for a suitable private contact route. Keep that initial
public request brief and omit exploit details, credentials, database contents,
or other sensitive information. No private reporting channel or response-time
commitment is assumed.

Once a suitable channel is agreed, include the affected commit, Node/npm versions,
source or container mode, expected/actual behavior, and minimal reproduction
steps using harmless data. See GitHub's guidance on
[privately reporting a vulnerability](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/report-privately).
